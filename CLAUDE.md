# Cinematic DevOps Website

## Objective
Build a premium cinematic website for a DevOps Project Series.
The experience should feel like a carefully art-directed engineering story,
not a generic template or standard course landing page.

## Before coding
1. Inspect the entire repository.
2. Read every skill under .claude/skills/.
3. Read every file under .kiro/steering/.
4. Inspect references/devops-website-reference.png if it exists.
5. Identify the current framework and implementation.
6. Plan the page sections before major changes.

## Design requirements
- Match the supplied reference as closely as practical.
- Preserve its composition, typography, spacing, colors, and hierarchy.
- Use distinct visual scenes for the hero, projects, architecture, technical details, and final CTA.
- Avoid generic card grids and repetitive landing-page sections.
- Use technically credible DevOps visuals.
- Never invent production metrics or customer claims.

## Motion requirements
- Use GSAP and ScrollTrigger for meaningful scroll-linked storytelling.
- Add restrained pointer-reactive effects where useful.
- Support mobile and reduced-motion preferences.
- Keep animations smooth, performant, and accessible.

## Engineering requirements
- Inspect files before modifying them.
- Reuse the existing framework when present.
- Keep code modular and maintainable.
- Do not overwrite existing work without inspection.
- Ensure navigation and buttons work.
- Run available development and production checks.

## Workflow
1. Analyze the reference and project.
2. Plan the visual system.
3. Implement the complete website.
4. Add responsive layouts and motion.
5. Run the application and inspect the result.
6. Compare screenshots against the reference.
7. Fix visual and functional issues.
8. Report completed work and limitations.

## Completion criteria
The site must build successfully, remain usable on mobile,
and preserve essential content when motion is disabled.
